# Adaptizer Player - React Native shell (mobile/)

This is the isolated React Native shell created for migration step **A01**
(see `REACT_NATIVE_MIGRATION_PLAN.md`, section "A01 - Create the isolated
React Native shell"). It is a separate app that can be installed side by
side with the legacy Android app under `app/`. It does not touch, depend
on, or build against the legacy app.

The current shell renders the React Native catalog and transport controls,
loads songs through the TypeScript repository, and uses the typed Android
TurboModule facade for native playback and Kotlin-owned adaptation. The
screen and player boundaries remain injectable so unit tests do not require a
device or network.

## Scaffold command used

```
npx --yes @react-native-community/cli@latest init AdaptizerPlayer \
  --directory mobile \
  --package-name com.adaptizerplayer.rn \
  --skip-git-init \
  --install-pods false \
  --pm npm
```

Run from the repository root. `--skip-git-init` was required because
`mobile/` lives inside the existing `Player` git repository.

## Versions

- React Native: **0.86.2**
- React: 19.2.3
- React Native Community CLI: 20.1.0
- Node: **v24.18.0** (see `.nvmrc`, pinned to major `24`)
- npm: **11.18.0**
- JDK: OpenJDK 21.0.5 (Android Studio's bundled JBR at
  `C:\Program Files\Android\Android Studio\jbr`)

`java` is not on PATH in this environment. Before any Gradle command, set:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
```

## Android configuration

- `applicationId` / `namespace`: **`com.adaptizerplayer.rn`** - a
  **temporary** debug-only ID (not the production
  `com.adaptizerplayer` ID) so this app installs side by side with the
  legacy app during migration.
- `minSdkVersion`: 24
- `compileSdkVersion` / `targetSdkVersion`: 35 (pinned down from the RN
  0.86 template's default of 36 to match what's actually installed in
  this environment - see "Known limitations" below - and to match the
  legacy app's SDK surface).

## Running

Install dependencies once:

```powershell
cd mobile
npm install
```

Run on Android (emulator running or device connected):

```powershell
npm run android
```

Or build a debug APK directly with Gradle:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
cd mobile\android
.\gradlew.bat assembleDebug
```

Type-check:

```powershell
cd mobile
npx tsc --noEmit
```

## Known limitations / follow-ups

- **Android NDK / CMake were not pre-installed** in this environment
  (only `platforms/android-35` and `build-tools/35.0.0` & `35.0.1` were
  present under the Android SDK, no `ndk/`, `cmake/` or
  `cmdline-tools/`). React Native's New Architecture builds native
  TurboModule/Fabric glue (`libappmodules.so`) via CMake and requires
  the NDK. The Android Gradle Plugin auto-downloaded and installed
  `ndk;27.1.12297006` and `cmake;3.22.1` on the first `assembleDebug`
  run (accepting the already-present SDK license), so no manual
  SDK Manager step was needed and the New Architecture was **not**
  disabled. If a future environment has no network access during the
  first build, pre-install those exact components via Android Studio's
  SDK Manager.
- `mobile/android/local.properties` (gitignored, like the legacy app's
  root `local.properties`) points `sdk.dir` at the local Android SDK and
  must exist locally for Gradle to resolve the SDK; it is not committed.
- iOS: `mobile/ios/` was generated by the template and is kept, but the
  adaptive-audio implementation remains Android-only. Android is the first
  target; iOS playback is a documented follow-up.
